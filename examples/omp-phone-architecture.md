## Level 3 — Request execution flow

Traced **`POST /message`** from `bridge/src/server.js` (client method `sendMessage` in `client/src/api.js`). Handler call-graph walk with parameter bindings.

Request body fields read in handler: `attachments`, `sessionId`, `async`, `text`.

Branch: `body.async` chooses `startMessage` (non-blocking) vs `sendMessage` (await completion).

```mermaid
sequenceDiagram
    autonumber
    actor User
    participant App as App
    participant Api as sendMessage
    participant HTTP as server.js
    participant Auth as isAuthorized
    participant Attach as storeMessageAttachments
    participant Resume as getResumeSession
    participant Store as SessionStore
    participant Push as PushNotificationRegistry
    participant Expo as Expo Push API
    User->>App: send text
    App->>Api: sendMessage()
    Api->>HTTP: POST /message
    HTTP->>Auth: Bearer / loopback check
    HTTP->>Attach: storeMessageAttachments
    HTTP->>Resume: getResumeSession
    HTTP->>Store: startMessage
    HTTP->>Store: sendMessage
    Store->>Push: sendNotification
    Push->>Expo: POST /api/v2/push/send
    HTTP-->>App: 200 JSON
```

| 2 | `User` → `HTTP` | `POST /message` | `bridge/src/server.js` |
| 3 | `HTTP` → `isAuthorized` | `Bearer / loopback check` | `bridge/src/server.js` |
| 4 | `HTTP` → `storeMessageAttachments` | `storeMessageAttachments` | `bridge/src/server.js` |
